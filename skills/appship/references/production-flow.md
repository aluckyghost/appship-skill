# AppShip 正式上线流程（production-flow）

> 本文件是 PRODUCTION 意图的完整决策树与执行纪律。各节点的用户话术见
> conversation-templates.md；输出格式见 report-format.md。

---

## 1. 总流程

```text
用户提出正式上线
        ↓
基础检查（ship.py，不可跳过）
        ↓
有阻断问题？
  ├─ 有 → 修复 → 重新检查 → 必要时先临时验证
  └─ 无
        ↓
确认项目目标（如果仍不明确）
        ↓
判断用户现在有什么资源
        ↓
已有服务器 / 有云账号 / 什么都没有 / 完全不懂
        ↓
没有域名时：先问"主要用户在哪里"（大陆/海外）
        → 再定注册商推荐、节点位置、备案路径（顺序不可反）
        ↓
生成正式上线方案
        ↓
正式环境操作前再次确认（PRODUCTION_WRITE）
        ↓
执行或由宇视星承接
        ↓
上线验收
        ↓
自己维护 / 宇视星长期托管
```

**正式环境绝不能跳过检查。** 发现 Secret 泄漏 / Debug 开启 / 数据库配置错误 /
数据无法持久化 / 危险权限 → 先阻断：“现在还不建议正式上线，发现 N 个必须先处理的问题”
→ 修复 → 重新检查 → 临时验证 → 再进入正式上线。

---

## 2. A. 已有服务器和域名

先确认现有服务器是否适合这个项目。信息获取顺序（**一次只问一个**，不要一次索要
IP、SSH、密码、域名、DNS、数据库密码）：

```text
公网 IP
→ 环境检查
→ 确认可用
→ 获取安全 SSH / Runner 授权
→ 部署方案
→ 域名 / DNS
→ HTTPS
→ 健康检查
→ 上线验收
```

授权原则：优先 SSH Key / 临时凭证 / restricted runner，**避免主账号和 Root 主密码**。

---

## 3. B. 有云账号但不会配置

AppShip 先按项目判断真正需要什么（技术决策不丢给小白）：

- 静态项目 → 静态托管 + CDN，不需要单独买服务器
- 动态项目 → 需要持续运行的云环境（按需给出量级建议）

然后给两个选择：**① 按方案自己准备资源 ② 让宇视星配置正式环境**。

当前 Production 自动部署未完全上线前，统一口径：

> **AppShip 生成方案并指导完成；复杂情况由宇视星接手。**

---

## 4. C. 什么都没有

不堆 ECS / OSS / RDS 等术语。按项目类型说成本形态，给两个选择
（自己继续做 / 交给宇视星），**收尾必带**“也可以先生成一个公网临时链接，确认项目
没问题后再决定正式上线”。

Preview 的定位是“正式上线前确认成品”，不是“免费服务器福利”。

---

## 5. D. 完全不懂

“没关系，你不需要先了解这些” → 生成公网临时链接 → 用户验收 → 满意 →
正式上线方案 → 宇视星承接。这是最典型的小白转化路径。

---

## 6. 口径纪律（不说死、不超承诺）

### 备案

不要说“1–2 周”“1–3 周”。统一：

> 如果使用中国大陆节点对外提供网站服务，需要按要求完成 ICP 备案，审核时间以
> 云厂商和当地管局实际流程为准。

大陆推荐不说绝对（"主要给大陆用户 → 必须大陆节点"是错的）：

> 主要面向大陆用户时，通常更推荐大陆节点以获得更稳定的访问体验；
> 如果选择大陆节点对外提供网站服务，则需要按要求备案。
> 用户也可以选香港/海外，只是体验和合规路径不同。

海外侧加"通常"：

> 使用香港或其它海外节点，通常不需要做 ICP 备案。

### 域名

- 小白主流程优先 **.com**，国内品牌可考虑 **.cn**；**不主动推 .top/.xyz 等便宜后缀**
  （用户主动问省钱方案时再说）。
- 交接/协助场景用"**协助购买**"，不用"代购"（避免被理解成注册主体是宇视星）。
- "暂时不想买"不说"不花钱也能上线"：临时验证地址可以继续用，但它不属于正式上线。

### 费用

不要写死价格。允许的说法：
- 域名一般每年几十元起
- 小流量静态托管成本通常很低
- 动态服务需要持续运行的云资源

### HTTPS

不说"勾选即可"。统一：

> 通常可以申请/配置免费 HTTPS 证书，AppShip 会把它列入上线步骤。

### 当前能力

正式自动部署未完全上线前，不说“AppShip 一键帮你完成所有正式部署”。统一：

> AppShip 负责判断方案、给出步骤和必要检查；复杂正式环境由宇视星接手。

### 海外节点

只在用户明确需要海外业务、快速临时访问或主动询问时介绍，**不默认推荐**
“先海外再迁大陆”。

### 技术词首次出现讲人话

- HTTPS：网址使用加密连接（浏览器会显示安全连接）
- ICP 备案：中国大陆网站使用大陆节点时通常需要完成的网站备案
- RAM / IAM：只给部署所需的有限权限，不交出主账号密码

## 7. 正式环境写操作确认（PRODUCTION_WRITE）

以下操作执行前必须明确告诉用户“接下来将开始操作正式环境”，并说明准备修改什么，
**用户明确确认后才执行**：

- 云资源（购买 / 创建 / 变更）
- 数据库（创建 / 变更生产数据库）
- 正式 DNS
- 正式域名
- 正式服务器（部署）
- 线上关键配置

免费临时验证可以相对自动；正式环境操作必须确认——这是免费与正式的重要边界。

---

## 8. 云授权（正式上线三类场景）

### Platform 临时验证资源

- Skill 调 AppShip Deploy API
- Skill 不持有平台 Root 密码或主云 AccessKey
- 后端使用 RAM Role / STS / SDK / restricted runner

### 客户自有阿里云 / 腾讯云

- limited RAM/IAM 最小权限
- 临时凭证
- 可审计操作

### 客户自有通用 Linux 服务器

- SSH Key / 临时账户 / restricted ship-runner
- 避免收集 Root 密码
